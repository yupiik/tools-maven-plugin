= Asciidoc Java: supported syntax

This page lists what the `asciidoc-java` parser reads, grouped by the part of a document it belongs to.
asciidoctor is the reference: where a construct has several readings, the parser takes asciidoctor's, and the notes below say so when the detail matters.
The xref:asciidoc-java.adoc[overview] introduces the module, and the xref:asciidoc-java-html.adoc[HTML] and xref:asciidoc-java-markdown.adoc[Markdown] pages say what each renderer writes for these constructs.

== Document header

* The document title (`= Document Title`), followed by the author line and the revision line.
* Authors, either with the author line (`firstname middlename lastname <mail>`, several authors separated by `;`, attribute entries being allowed before it) or with attribute entries (`:author:` and `:email:` for one author, `:authors:` or `:author_<n>:` and `:email_<n>:` for several).
* The revision line (`v1.0, 2013-01-01: the remark`; a revision number without a date needs the `v` prefix).
* The attributes deduced from the header (`authorcount`, `authors`, `firstname`, `middlename`, `lastname`, `authorinitials`, `revnumber`, `revdate`, `revremark` and their `_<n>` variants), the attribute entries of the document winning over the values deduced from the author line; `Author` also exposes the deduced names.
* Attribute entries (`:name: value`, `:!name:` to unset) and conditionals in the header, see <<_includes_and_conditionals,Includes and conditionals>>.
* The man page doctype (`= commandname(1)`).

IMPORTANT: as in asciidoctor, the document header ends on the first empty line, so the line after the title is always the author line unless it is an attribute entry or a preprocessor directive such as `ifeval::[{version} > 1]`. A section or a list that follows the title without an empty line becomes an author.

== Sections and titles

* Section titles (`== Section`, `=== Sub section`) and section numbering (`:sectnums:`).
* Discrete headings (`[discrete]` or `[float]` above a heading): a title block that opens no section, ends none and stays out of the table of contents.
* Special sections (`[appendix]`, `[bibliography]`, `[glossary]`, `[index]`).
* Block titles, a `.Title` line or `title=` on the attribute line above a paragraph, an admonition, a list, a code block, a table, an image or an open block, written as asciidoctor writes them (`<div class="title">`, a `<caption>` for a table).
* The table of contents (`:toc:`, with `toclevels` and `toc-title`); the xref:asciidoc-java-html.adoc#_attributes_the_renderer_reads[HTML] and xref:asciidoc-java-markdown.adoc#_what_each_construct_becomes[Markdown] pages say where each renderer writes it.

=== Section ids

A section without an explicit id gets the id asciidoctor gives it: the title in lower case, without its markup and punctuation, after `idprefix` (`_` by default), with each run of spaces, dots and hyphens replaced by `idseparator` (`_` by default).
When an earlier section or block already has that id, the separator and a number follow it: `_same_2`, `_same_3`.
A title with a typographic replacement such as `--`, a footnote or a counter can still get another id than in asciidoctor.
With an empty `:idprefix:` and `:idseparator: -`, `== Vert.x and the Getting-started guide` gets `vert-x-and-the-getting-started-guide`; up to version 1.2.16, it got `vertxandthegettingstartedguide`.

== Paragraphs and inline text

* Paragraphs and text formatting (`*bold*`, `_italic_`, `+monospace+`), the inline role `[.role]#text#` and the `%` option prefix.
* Attributes and substitutions (`{name}` references, `\{name}` to escape one). When neither the document nor the configuration defines an attribute, the renderers leave its reference literal.
* Inline passthroughs in a code span: the text between single, double or triple plus signs inside the backticks is written as it is, without attribute substitution, and so is a double-plus run inside a longer code span; a span opening with a passthrough ends after it, so that passthrough can hold a backtick.
* Footnotes, index terms and counters.
* Inline STEM (`$...$`, `stem:[...]`).
* Bare email autolinks (`user@example.com`).

== Lists

* Unordered lists (`*`) and ordered lists (`.`), nested at any depth, `[start=NN]` on an ordered list.
* Description lists, with the `[qanda]` and `[horizontal]` styles.
* Callout lists after a code block, see <<_blocks,Blocks>>.

== Links, cross references and anchors

* Links (`link:url[text]`) and bare URLs.
* The text of a link, `link:url[text]`, `https://url[text]` or `xref:id[text]`, is an attribute list only when it holds a `=`, as in asciidoctor: `link:url[a, b]` keeps `a, b`, `link:url[example]` keeps `example` and `link:#id[a."b".c]` keeps its double quotes, while `link:url["a, b",role=x]` gives the text `a, b` and the role `x`. In that list a `name=value` is read only when the name starts with a word character and holds word characters, `-` or `.`, so the text of `link:url[+`a=b`+,role=x]` stays `a=b`, and the `.role`, `#id` and `%option` shorthands of a block attribute line do not apply, so `link:url[.foo,role=x]` keeps the text `.foo`. A `mailto:` text is split at its commas only when it holds one, where asciidoctor reads the subject and the body; the renderers write only the text before the first comma.
* Cross references (`<<id>>`, `<<id,text>>`, `<<page.adoc#id,text>>`, `xref:page.adoc#id[text]`). As asciidoctor reads the `<<...>>` form, the part before a `#` is always a page, whatever its extension, and a target without `#` is always an id, so `<<page.adoc>>` links the id `page.adoc` where `xref:page.adoc[]` links the page.
* Block ids, written `[#id]`, `[id=name]` or as an anchor line `[[id]]` (`[[id, reftext]]` with a reference text) above a block or the document title.
* Inline anchors, `[[id]]` or `[[id, reftext]]`, written as an empty `<a id>` when text follows them on the line, as asciidoctor does; at the end of a line, the anchor stays the id of the text before it.
* Bibliography and glossary entries (`[[[ref]]]`).

== Images, media and other macros

* Images (`image:path[alt]`), audio and video with controls, YouTube and Vimeo embeds.
* The `icon:`, `btn:`, `kbd:`, `menu:`, `xref:`, `footnote:` and `toc::[]` macros. The keys of `kbd:` are split on the first `,` or `+` after the first character, so `kbd:[Ctrl,Shift]` and `kbd:[Ctrl+Shift]` are both two keys and `kbd:[Ctrl++]` is `Ctrl` and `+`.
* An inline macro starts where its name stands, as in asciidoctor: the target is the run without blanks before the `[`, up to its first colon, and the name is the run of word characters and hyphens before that colon, so `Environment variable: env_var:X[]` keeps `Environment variable: ` as text, `name.footnote:[..]` is a footnote and `Time: 10:00 [foo]` holds no macro. The parser has no registry of names, so every name is read the same way: `hyperlink:x[y]` is a macro named `hyperlink`, where asciidoctor reads `hyper` then a link.
* The macros of the `blank-target-macros` attribute also take a target holding blanks, as `image:my file.png[alt]`, see <<_parser_attributes,Parser attributes>>.
* A macro with another name, such as `tooltip:foo[a hint]`, stays in the model as a `Macro` element. Both renderers write it as text by default, as asciidoctor does with a macro no extension registers, or ignore it or fail on it when their `unknownMacro` option or attribute asks for it, and a subclass of a renderer renders it in `onMissingMacro`; see xref:asciidoc-java-html.adoc#_unknown_macros[the HTML renderer] and xref:asciidoc-java-markdown.adoc#_unknown_macros_and_includes[the Markdown renderer].
* Mermaid diagrams, and `ascii2svg` diagrams rendered by the xref:ascii2svg.adoc[ascii2svg] module.

== Blocks

* Source blocks (`[source,...]`), listing blocks, example blocks, open blocks, quote blocks and sidebars.
* Admonitions (`NOTE:`, `TIP:`, `IMPORTANT:`, `WARNING:`, `CAUTION:`), as a paragraph or as a delimited block.
* Block STEM (`[stem]`, `[latexmath]`, `[asciimath]`) and passthrough blocks.
* Callouts: `<1>` markers in a code block and the callout list after it. A block whose markers do not match its list fails the parse, unless the `callout-mismatch` attribute asks to keep it, see <<_parser_attributes,Parser attributes>>.
* Shorthands on a block style, `[NOTE#note.important%collapsible]` giving the style `NOTE`, the id `note`, the role `important` and the option `collapsible`, and chained options, `[%collapsible%open]`. A line without a style keeps the whole shorthand as one value, so `[#io.yupiik.test.MyObject]` is that id.
* Quoted values of named attributes, `[title="One, two"]` or `[title='One, two']`, on a block attribute line as in a macro (`link:url[text,window='_blank']`): as in asciidoctor, the quotes are not part of the value and keep its commas, `\'` is a quote inside single quotes, and a single quote that is never closed stays text. A single-quoted positional value, such as `xref:page.adoc['Getting started']`, keeps its quotes. A `\"` inside a double-quoted value is a quote, an unclosed quote is text, and the `%` option shorthand is not read inside a quoted value, so `[cols="15%,15%",options="header"]` is two columns with a header row.
* A collapsible example block (`[%collapsible]`, or `opts=collapsible` on a `====` block), `%open` opening it. As in asciidoctor, the option collapses an example block only, not an open block or a sidebar.

== Tables

* Tables (`|===`) with cell specifiers before `|`: a span (`2+`, `.2+` or `2.3+`), a duplication factor (`3*`), an alignment (`^`, `>` or `.^`) and a style (`a`, `d`, `e`, `h`, `l`, `m` or `s`), at the start of a line or after a blank. The cells are put into rows by column count.
* The header option, `autowidth`, `stripes` and the column alignments of `cols`.
* Markdown pipe tables (`|---|`).
* A conditional inside a table is evaluated while the rows are read, see <<_includes_and_conditionals,Includes and conditionals>>.

== Includes and conditionals

* Include directives (`include::file.adoc[]`) with `tag`, `tags`, `lines`, `leveloffset` and `indent` filtering. The `ContentResolver` of the `ParserContext` reads the target. A missing target fails the parse, unless the include is optional (`opts=optional`) or the document sets `:missing-include: ignore`, see <<_parser_attributes,Parser attributes>>. The parser resolves includes, so an `include` macro never reaches a renderer.
* Conditionals (`ifdef::[]`, `ifndef::[]`, `ifeval::[]` with `else::[]` and `elsif::[]`), in the document header as in the body, the condition of `ifeval` written in its brackets as asciidoctor requires (`ifeval::[{version} > 1]`), the inline form `ifdef::name[content]`, and multi-attribute conditions (`name1,name2` for an or, `name1+name2` for an and).
* A conditional block stays in the model, and each renderer writes the branch that holds with the attributes it knows at rendering time. As asciidoctor removes the directive lines before parsing, conditional lines inside a paragraph, a list item or an admonition stay in that paragraph, joined with a space like its other lines, and a conditional paragraph between blank lines stays a paragraph of its own.
* Inside a table, the parser evaluates the directive while it reads the rows, with the attributes it knows at that point (the document attributes and its own), as asciidoctor's preprocessor does, so an attribute given only to a renderer does not change the rows.

== Markdown syntax

The parser also reads a subset of CommonMark, mixed freely with the AsciiDoc syntax.

[cols="1,2",options="header"]
|===
|Construct |Meaning

|`**bold**`, `~~strikethrough~~`
|Bold text, struck text.

|`` `code` ``
|Inline code.

|`[text](url)`, `![alt](url)`
|A link, an image.

|`# Heading`
|A section title, the level following the number of `#`.

|`---`, `***`, `___`
|A horizontal rule.

|Pipe tables, the cells separated by the pipe character and the header row followed by a `---` row
|A table.

|`**** content ****`
|A sidebar block.

|Two trailing spaces at the end of a line
|A hard line break (`<br>`).
|===

== Parser attributes

These attributes change how the parser reads a document.
Set them in the document (`:keep-paragraphs: false`) or pass them to the `Parser` constructor to apply them to every document.

[cols="1,1,4",options="header"]
|===
|Name |Default |Description

|`blank-target-macros`
|`image,icon,menu,xref`
|The inline macros whose target can hold blanks, as `image:my file.png[alt]`; every other target stops at a blank, as in asciidoctor. Add `link` for a document whose links hold blanks in their target. An empty value stops every target at a blank.

|`callout-mismatch`
|unset
|`ignore` keeps a code block whose callout markers do not match the callout list after it, without the unmatched markers and items. By default the parser fails on such a block.

|`keep-paragraphs`
|`true`
|Each paragraph of the blocks of an admonition block, a list item, a callout item or an `a\|` table cell stays a `Paragraph`, also when it holds one text. `false` gives the model of the versions before this attribute: the parser replaces such a paragraph with its text, so `* **First**` followed by a `+` continuation paragraph `Second` gives the same model as `* **First**Second`.

|`missing-include`
|unset
|`ignore` keeps parsing when the target of an `include::[]` does not exist: the include leaves no text and the warning listener of the parser (`Parser.Configuration.setWarning`) is told, where asciidoctor writes an `Unresolved directive` line in the output. By default a missing target fails the parse, unless that include is optional (`opts=optional`).
|===

== Differences from asciidoctor

The parser aims at asciidoctor's reading of every construct; these differences are known:

* The parser has no registry of macro names, so `hyperlink:x[y]` is a macro named `hyperlink`, where asciidoctor reads `hyper` then a link.
* A section title with a typographic replacement such as `--`, a footnote or a counter can get another id than in asciidoctor, see <<_section_ids,Section ids>>.
* The HTML renderer writes an icon macro as an `<i>` tag whatever the `icons` attribute says, where asciidoctor writes the text `[name]` without `icons` and an image with `icons=image`, see xref:asciidoc-java-html.adoc#_icons_and_icon_fonts[Icons and icon fonts].
* A missing include that `:missing-include: ignore` tolerates leaves no text, where asciidoctor, which has no such attribute, writes an `Unresolved directive` line; a missing include with `opts=optional` leaves no text in both.
* The HTML renderer writes the table of contents at the top of the document whatever the value of `toc`, and again at each `toc::[]` macro, where asciidoctor places it once, at the top, after the preamble or at the macro, see xref:asciidoc-java-html.adoc#_attributes_the_renderer_reads[Attributes the renderer reads].
* With `icons` set to another value than `font`, the HTML renderer reads the callout images under that value (`image/callouts/1.png`), where asciidoctor reads them under `iconsdir`.
* The HTML renderer writes an icon with the classes of the icon font the site picks, Font Awesome 5 by default (`fas fa-lock`), where asciidoctor writes the version 4 classes (`fa fa-lock`); a name written with its classes, `icon:fas fa-gift[]`, is kept as it is, where asciidoctor writes `fa fa-fas fa-gift`, see xref:asciidoc-java-html.adoc#_icons_and_icon_fonts[Icons and icon fonts].
* With `:sectnums:`, the entries of the table of contents have no section number (`One` for the heading `1. One`), where asciidoctor numbers them.
* Constructs that are not listed on this page are not implemented yet; a document using one renders them as text or fails, and an issue on the bugtracker is welcome.
