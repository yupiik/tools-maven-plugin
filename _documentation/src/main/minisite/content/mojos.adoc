= Maven Plugin
:minisite-index: 200
:minisite-index-title: Maven
:minisite-index-icon: building
:minisite-index-description: Maven Plugin integration.

To learn about all the goals of the Maven plugin, read the dedicated xref:mojo/yupiik-tools-maven-plugin.adoc[Yupiik Tools Maven Plugin] page.
The plugin, like every module of this repository, requires Java 17.

== Chain plugins

Mojos can be chained from the command line, without a pom declaration.

For example, the `git-report` and `pdf` mojos can be chained:

[source,bash]
----
mvn \
    io.yupiik.maven:yupiik-tools-maven-plugin:$version:git-report \
    io.yupiik.maven:yupiik-tools-maven-plugin:$version:pdf \
    -Dyupiik.workDir=work \
    -Dyupiik.git-report.dotGit=/path/to/project/.git \
    -Dyupiik.git-report.target=log.adoc \
    -Dyupiik.pdf.source=log.adoc \
    -Dyupiik.pdf.target=.
----

== PDF and latex formula

You can enable LaTeX formula support in PDF by adding the related dependency:

[source,xml]
----
<plugin>
  <groupId>io.yupiik.maven</groupId>
  <artifactId>yupiik-tools-maven-plugin</artifactId>
  <configuration>
    <!-- ... -->
  </configuration>
  <dependencies>
    <dependency>
      <groupId>org.scilab.forge</groupId>
      <artifactId>jlatexmath</artifactId>
      <version>1.0.7</version>
    </dependency>
  </dependencies>
</plugin>
----

Then use it as follows:

[source,asciidoc]
----

[jlatexmath]
--
x = a + b
--

This formula (jmath:_[a + b]) is cool.
----

== Pom-less PDF rendering

You can render an AsciiDoc file without a pom or a pom declaration:

[source,bash]
----
mvn \
  io.yupiik.maven:yupiik-tools-maven-plugin:$version:pdf \
  -Dyupiik.pdf.source=content.adoc \
  -Dyupiik.pdf.target=.
----

== Minisite

xref:mojo/minisite.adoc[minisite] can push the minisite to a remote target (often Git-backed pages).

Here is the related documentation.

The configuration supports a `git` entry if you want to upload the generated website to a Git branch (like `gh-pages`):

[options="header",cols="1,m,2"]
|====
|Name|Type|Description
|branch|String|Git branch to update (defaults to `refs/heads/gh-pages`).
|username|String|Username, used when the server of `serverId` has no password.
|password|String|Password, used when the server of `serverId` has no password.
|serverId|String|Server id used to read the username and password from settings.xml; defaults to `project.scm.url`. If no server matches, the host of `project.scm.url` is tried; one of the two must match. With an SSH Git URL, you can set the passphrase and the privateKey location in the server.
|url|String|Git URL.
|ignore|boolean|Whether the execution is skipped; lets you set it from a Maven variable.
|prefix|String|Prefix prepended to the files in the Git repository (ex: `public/`).
|noJekyll|boolean|Writes a `.nojekyll` file when `true` (the default).
|envBase64SshKey|String|Environment variable from which the base64-encoded private key is read, useful on CI; defaults to `YUPIIK_MINISITE_DEPLOY_KEY`. Note that the `<value>_PH` environment variable must contain the associated passphrase.
|====

The configuration also supports an experimental export to Atlassian Confluence.
It only works with the default template and requires a configuration similar to `git` or `ftp` exports:

[source,xml]
----
<profile> <!--  mvn clean package -Pconfluence  -->
  <id>confluence</id>
  <build>
    <plugins>
      <plugin>
        <groupId>io.yupiik.maven</groupId>
        <artifactId>yupiik-tools-maven-plugin</artifactId>
        <executions>
          <execution>
            <id>confluence</id>
            <phase>prepare-package</phase>
            <goals>
              <goal>minisite</goal>
            </goals>
            <configuration>
              <confluence>
                <ignore>false</ignore>
                <url>https://base.atlassian.net/wiki/</url> <!-- for cloud, for an on premise instance the /wiki/ is not always needed -->
                <authorization>Basic base64_value_of(your mail:your token)</authorization>
                <space>YOURSPACE</space>
                <skipIndex>false</skipIndex> <!-- if true, will skip all index.html files -->
              </confluence>
            </configuration>
          </execution>
        </executions>
      </plugin>
    </plugins>
  </build>
</profile>
----

IMPORTANT: The nested support of this exporter is very experimental, and we recommend that you keep only one level of `.adoc` files when using it.

=== Confluence Limitations

* Assets are not uploaded, so make sure to configure Asciidoctor to embed all assets in HTML,
* It only works with the default theme, since metadata is extracted from it to update the space,
* To look nice, you may need to tune the Confluence space CSS to import the styling of admonitions, code blocks, ... (this can require admin permissions).

=== Blog

The blog is supported if pages contain at least one blog attribute.
Here is the list of available attributes you can use:

* `:minisite-blog-published-date: yyyy-MM-dd`: when the page will be rendered (if not set it is always rendered).
* `:minisite-blog-categories: c1,c2`: comma-separated list of categories of this post.
* `:minisite-blog-authors: My, Myself`: comma-separated list of author names.
* `:minisite-blog-summary: Some short description.`: the summary of this post used on post list pages.

Blog page example:

[source,asciidoc]
----
= My Post
:minisite-blog-published-date: 2021-02-16T16:00
:minisite-blog-categories: others,simple
:minisite-blog-authors: Romain Manni-Bucau
:minisite-blog-summary: Second post.

Bla bla
----

=== Pre-Action

Pre-actions generate content from the project.
They are typically used to generate configuration from code or things like that.
They use the documentation module classpath.
Actions must implement `Runnable` and can have some (public) constructor parameters (parameters are matched by name, so make sure to enable `-parameters` in the Maven compiler plugin):

* `configuration` (`Map<String, String>`): the action configuration; it lets you reuse it if needed or write generic actions
* `sourceBase` (`Path`): the base directory you can generate `.adoc` into (generally where your sources are; tip: use a `generated` folder to be able to exclude it in `.gitignore` if desired)
* `outputBase` (`Path`): the base directory where you can generate HTML assets directly

==== Maven Plugin

Using `type=maven-plugin` (recommended) or `type=io.yupiik.maven.service.action.builtin.MojoDocumentationGeneration` you can get a `plugin.xml` file parsed to generate:

. One file per goal with some usage, the goal description and parameters (named `<goal>.adoc`)
. One file listing all goals (named `<goal-prefix>-maven-plugin.adoc`)

The configuration of this action is:

. `pluginXml`: file path or resource to find the `plugin.xml` file.
. `toBase`: where to generate the `adoc`.
. `description`: a global plugin description for the "listing" page (default is empty and page will just list goals).

==== Copy

Using `type=copy` (recommended) or `type=io.yupiik.maven.service.action.builtin.CopyFile` will copy a file from a source to a destination.
It is typically useful for assets (`openapi.json` for example).

. `from`: source file.
. `to`: destination.

==== JSON-Schema

Using `type=jsonschema` (recommended) or `type=io.yupiik.maven.service.action.builtin.JsonSchemaGenerator` will generate a JSON-Schema from a class:

. `class`: the class to generate the schema from.
. `to`: destination of the schema.
. `type`: `JSON` for a raw JSON-Schema (default) or `ADOC` for a textual, AsciiDoc output.
. `setClassAsTitle`: `true` to force object title to be the class name.
. `useReflectionForDefaults`: `true` to force reflection to try to extract defaults of attributes.
. `pretty`: when type=JSON, whether the JSON is prettified (default=true).
. `levelPrefix`: when type=ADOC, a title prefix (`==` for example), `=` by default.
. `title` and `description`: the title and description of the class in its JSON schema. They are required for type=ADOC.
. `annotationOnlyProvidesTheDescription`: `true` to never take the title from an annotation (`@Description(value)` case).

NOTE: The model classes can use a custom `@Description(title,description)` annotation (note that `@Doc` is also supported and the `value` method can be used instead of `description`).
See `JsonDocExtractor` for more details.

==== JSON-Schema to asciidoc

Using `type=jsonschema2adoc` (recommended) or `type=io.yupiik.maven.service.action.builtin.JsonSchema2AdocGenerator` will generate an AsciiDoc document from a JSON-Schema file (intended mainly for Fusion):

. `schema`: location of the schema (JSON).
. `root`: key under `schemas` map of the root schema to generate a doc for.
. `levelPrefix`: prefix to set for title (default `=`).
. `output`: where to generate the `.adoc`.

==== OpenMetrics renderer

Using `type=openmetrics2adoc` (recommended) or `type=io.yupiik.tools.minisite.action.builtin.OpenMetricsToAsciidoc` will generate AsciiDoc from an OpenMetrics export.

. `source`: path of the OpenMetrics dump.
. `to`: destination of the AsciiDoc generated from `source`.
. `levelPrefix`: a prefix set before the part title (`== ` by default for a second level title).
. `legend`: should tables have a legend (name of the metric), defaults to `true`.
. `header`: prefix the whole rendering (lets you set a title and some options if needed).

==== Yupiik Batch simple-configuration renderer

Using `type=simple-configuration` (recommended) or `type=io.yupiik.tools.minisite.action.builtin.SimpleConfigurationGenerator` will generate AsciiDoc from the configuration class passed in the `class` `<configuration>` option.

. `class`: root configuration fully qualified name.
. `output`: where to generate the `.adoc`.

==== Download and Unzip

Using `type=download-unzip` (recommended) or `type=io.yupiik.tools.minisite.action.builtin.DownloadAndUnzip` downloads a zip from an HTTP URL, then extracts it, fully or partially, into a particular folder.
This can be used to download a Git repository using the GitHub/GitLab/Gitea API for example.

. `url`: the zip URL.
. `subpath`: the subpath to copy in `target`. It filters the zip entry names by prefix.
. `headers`: in properties format, a set of headers to set.
. `target`: where to copy the selected files.
. `workdir`: the folder the zip is downloaded to; a temporary folder if not set.

==== Replace string in file

Using `type=replace-in-file` (recommended) or `type=io.yupiik.tools.minisite.action.builtin.ReplaceInFile` will rewrite a text file, replacing a string with another one.

. `source`: file to rewrite.
. `token`: text to replace.
. `replacement`: text replacing `token`.

TIP: Using `regex{xxx}` as `token` will use a Java regex to do the replacement.

=== Example

[source,xml]
----
<plugin>
  <groupId>io.yupiik.maven</groupId>
  <artifactId>yupiik-tools-maven-plugin</artifactId>
  <executions>
    <execution>
      <id>build-and-deploy-doc</id>
      <phase>package</phase>
      <goals>
        <goal>minisite</goal>
      </goals>
      <configuration>
        <siteBase>https://yupiik.github.io/${project.artifactId}</siteBase>
        <logoText>My Product</logoText>
        <indexSubTitle>The top product.</indexSubTitle>
        <ftp>
          <serverId>http://mini.yupiik.net</serverId> <!-- default is siteBase -->
          <url>ftp://ftpupload.net/htdocs</url>
        </ftp>
      </configuration>
    </execution>
  </executions>
</plugin>
----

=== Page attributes

Some specific attributes customize the generation:

* `minisite-skip` skips the rendering of an `.adoc` file even when it is not in the `_partials` directory, whatever its value.
* `minisite-path=<string>` forces the relative path of the output file: for example, a file named `foo-bar.adoc` with the attribute `minisite-path` set to `foo/bar.html` is written to `foo/bar.html` instead of `foo-bar.html`. Note that links are not rewritten, so link to this page with `+link:.....html[]+` instead of `xref`.
* `minisite-highlightjs-skip` disables highlight.js for the page (useful with swagger-ui for example).
* `minisite-nav-prev-label`/`minisite-nav-next-label` adds a "previous"/"next" link to another page at the bottom of the page; this attribute defines its label.
* `minisite-nav-prev-link`/`minisite-nav-next-link` adds a "previous"/"next" link to another page at the bottom of the page; this attribute defines its link (the label is required). If the label is defined but not the link, the link is the label in lower case, with hyphens instead of spaces and the `.html` extension.
* `minisite-breadcrumb` defines a page breadcrumb (navigation tree) at the top of the content. The syntax is: `:minisite-breadcrumb: Home[#] > Another Page[link-to-another-page.html] > This page`. If there is a `[xxx]`, then `xxx` is used as a link.

TIP: For good documentation, the nav and breadcrumb features are highly recommended.

=== Index generation

To include a page in the index, give it the `minisite-index` attribute.
Its value is the order of the entry in the index tiles.

TIP: Use `100`, `200`, ... rather than `1`, `2`, `3`, ..., so that an item is easy to insert later.

* `minisite-index-title` attribute enables to override link text.
* `minisite-index-icon` attribute enables to override font awesome icon (without `fa-` prefix).
* `minisite-index-description` attribute enables to override the text in the index tile for the page entry.

=== Left menu

The left menu of a page is defined by `minisite-menu-<position>` attributes, read from the page attributes, else from the `attributes` of the plugin configuration, with both engines.
A page attribute wins over the configuration attribute of the same name, so a site usually defines one menu in the configuration and a page can change an entry of it in its header (with the Asciidoctor engine, the configuration attributes are locked by Asciidoctor itself unless their value ends with `@`, as for any attribute set by the API).
The value of an entry is the path of its target from the site root, with or without the `.html` extension when it names a page, or a URL (`https://...`), which is linked as written:

[source,asciidoc]
----
:minisite-menu-1: /getting-started.html
:minisite-menu-1-title: Getting Started
:minisite-menu-1-icon: home
:minisite-menu-1-1: /installation.html
:minisite-menu-1-2: /configuration.html
:minisite-menu-2: /guides.html
----

[options="header",cols="1,3"]
|===
|Attribute|Meaning
|`minisite-menu-<n>`|A top level entry, numbered from 1. `minisite-menu-<n>-<m>` is an entry under it, numbered from 1 again, at any depth. The entries are read until the first missing number, so a gap in the numbering ends the list, and an attribute which is not a position is ignored.
|`minisite-menu-<position>-title`|The text of the entry, by default the `minisite-index-title` attribute or the title of the target page, or the value itself when it is not a page of the `content` folder.
|`minisite-menu-<position>-icon`|The font awesome icon of the entry (`home` or `fa-home`), by default the icon of the target page (its `minisite-index-icon` attribute) for a top level entry; a nested entry, or an entry which is not a page, has no icon unless this attribute sets one.
|`minisite-left-menu-prefix`|Written before each entry starting with a slash: with `/docs`, the entry `/getting-started.html` links to `/docs/getting-started.html`. Alone, without `minisite-menu-1`, it defines no menu.
|===

The `left-menu.hb` template gets `listItems`, the entries rendered with `left-menu-item.hb`, and `items`, the entries as a list a custom template can iterate with `{{#each items}}`: each one has `href`, `text`, `title`, `icon`, `items` (the entries under it) and `children` (these entries rendered as a nested list), plus the model of the page it links to.
A page without `minisite-menu-1` shows the menu built from the `minisite-index` attributes of the pages, which is deprecated, logs a warning and gives the template `listItems` only.

== Maven Asciidoctor Macro

The project adds AsciiDoc macros that read some Maven build information.
Note that the mojo that renders the document must run in the right lifecycle phase when a macro uses project metadata (the plugin does not require any resolution, so it can be used standalone).

=== maven_dependencies

This macro lists the project dependencies.

==== Usage

[listing]
....
[maven_dependencies,scope=compile]
--
--
....

Scope can be:

- compile
- runtime
- compile+runtime
- runtime+system
- test
- provided_only
- compile_only
- test_only
- system_only

== Yupiik OSS extension

This extension sets up the equivalent of a parent pom but lets you inherit, or not, from another parent and get plugin upgrades by changing only the extension version.

It is configured in the root project through Maven properties:

[source,xml]
----
<properties>
  <!-- REQUIRED: enable the extension -->
  <yupiik.oss.enabled>true</yupiik.oss.enabled>
  <!-- OPTIONAL: defaults -->
  <yupiik.oss.java.version>11</yupiik.oss.java.version>
  <yupiik.oss.encoding>UTF-8</yupiik.oss.encoding>
  <yupiik.oss.javadoc.doclint>none</yupiik.oss.javadoc.doclint>
</properties>
----

`yupiik.oss.sign.skip` set to `true` skips the signature and `false` forces it; without it, the artifacts are signed only when the `release` profile of the pom is active, which is why the example below declares an empty one.

Just enabling this extension upgrades a few plugins, enforces the encoding and Java version, enforces the license check and much more.

See `io.yupiik.maven.extension.YupiikOSSExtension.afterProjectsRead` for details.

=== Example

[source,xml]
----
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>

  <!-- ... -->

  <properties>
    <yupiik.oss.enabled>true</yupiik.oss.enabled>
  </properties>

  <build>
    <extensions>
      <extension>
        <groupId>io.yupiik.maven</groupId>
        <artifactId>yupiik-tools-maven-plugin</artifactId>
        <version>${yupiik-tools.version}</version>
      </extension>
    </extensions>
  </build>

  <profiles>
    <profile>
      <id>release</id>
    </profile>
  </profiles>
</project>
----

== Inline pom contributor extension

It lets you put a `YupiikContributor.java` file in each module, which is compiled and executed in the `afterProjectsRead(MavenSession)` callback.

Example:

[source,java]
----
import org.apache.maven.AbstractMavenLifecycleParticipant;
import org.apache.maven.execution.MavenSession;
import org.codehaus.plexus.component.annotations.Component;

@Component(role = AbstractMavenLifecycleParticipant.class, hint = "my-module-customizer")
public class YupiikContributor extends AbstractMavenLifecycleParticipant {
    @Override
    public void afterProjectsRead(final MavenSession session) {
        System.out.println(">>>> hello: " + session);
    }
}
----

This lets you handle the pom programmatically (mainly intended for plugins since dependencies are not synchronized in Maven poms when contributed this way).

To enable it, enable the related extension:

[source,xml]
----
<build>
  <extensions>
    <extension>
      <groupId>io.yupiik.maven</groupId>
      <artifactId>yupiik-tools-maven-plugin</artifactId>
      <version>${yupiik-tools-maven-plugin.version}</version>
    </extension>
  </extensions>
</build>
----

TIP: See `io.yupiik.maven.extension.YupiikOSSExtension` for a more complex participant example.

== Crypt mojos

Crypt mojos are intended to encrypt/decrypt (with the `AES/CBC/PKCS5Padding` algorithm, like link:https://maven.apache.org/guides/mini/guide-encryption.html[Maven default encryption]) values.
It supports either inline values or properties files.

TIP: It is a simple way to handle secrets in a bundlebee placeholder properties file on CI/CD if you don't have a vault or an equivalent mechanism for GitOps.

=== Value based mojo

`yupiik-tools:crypt-value` encrypts a value (symmetrically, `decrypt-value` decrypts a value).

Configuration is:

* `value`: the value to crypt (decrypt),
* `useStdout`: should the value be printed using Maven logger or simply `stdout`,
* `masterPassword`: the master password for the ciphering.

=== Properties based mojo

`yupiik-tools:crypt-properties` encrypts the values of a properties file (symmetrically, `decrypt-properties` decrypts them).

Configuration is:

* `input`: path to the properties file to crypt (decrypt) *values* for (keys are never encrypted),
* `output`: path to the properties file which will contain encrypted (decrypted) data,
* `masterPassword`: the master password for the ciphering,
* `includedKeys`: a list of values (direct key), `starts:<some prefix>` prefixes or `regex:<pattern>` regex to filter the values to encrypt (decrypt) based on their keys,
* `excludedKeys`: a list of values (direct key), `starts:<some prefix>` prefixes or `regex:<pattern>` regex to filter the values to *NOT* encrypt (decrypt) based on their keys,
* `preserveComments`: whether `output` keeps the comments and the structure of `input` (property `yupiik.crypt-properties.preserveComments`, default `true`).

IMPORTANT: By default, `output` keeps the comments and the structure of `input`; with `preserveComments` set to `false`, the keys are sorted and the comments dropped. An already encoded value will not be re-encoded.
This last point lets you set `input`=`output` to encrypt a file in place.
